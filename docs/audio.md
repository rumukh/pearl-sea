# Perlové moře audio

The game's music and sound effects, their formats, the manifest the shell reads, the loudness and
memory budgets, and how every file was made. S5 owns the pack (`assets/audio/**`,
`scripts/audio/**`, this file); S4 owns the runtime map from game events to sounds
([app.md](app.md)). The umbrella policy is [assets.md](assets.md): **local models only**, never a
cloud generator.

## 2. Format

- **Ogg Vorbis, mono, 48 kHz.** The shell's AudioContext runs at 48 kHz, so nothing is resampled
  on decode and the music keeps its full bandwidth. Decoded audio is held as 32-bit floats at the
  context rate (192 kB per second of mono), so the pack is mono: stereo would double the memory.
- **Loops are a whole number of frames at 22.05, 44.1 and 48 kHz** (a multiple of 320 samples at
  48 kHz), so a loop decoded at any common rate keeps an exact period.
- **No metadata**: the only Vorbis comment is the encoder tag. No titles, dates, prompts or paths.
- Vorbis quality 5 (about 80 kbit/s mono): the five music files total 2.3 MB, the 39 effects
  0.47 MB (as 16-bit PCM WAV they would take 3.3 MB, and push the offline pack over its budget).
- **The effects' identity is their PCM**: the synthesizer renders 16-bit PCM byte for byte on every
  platform, but an encoder's bytes depend on its version, so each Ogg is encoded once from that PCM
  and an effect is encoded again only when its PCM changes (§7).
- Decoders end a short Vorbis stream differently: libvorbis returns exactly the stream's length,
  FFmpeg's decoder (Chrome's is FFmpeg) may drop its last 128 samples or keep up to a block of the
  encoder's padding. The encoding step checks that whatever may be dropped or added is silent
  (below -50 dBFS); the manifest's durations are the streams' exact lengths.

## 3. The manifest

`assets/audio/manifest.json` (schema `pearl-sea-audio-manifest/1`, Dragon Valley's format renamed)
is **generated**: `node scripts/audio/manifest.mjs` reads `assets/audio/recipes/_manifest.json` and
measures every file from its own Ogg headers. Never edit the manifest by hand.

- `sounds`: `id`, `src`, `bus` (`music` or `effects`), `durationSeconds` (what the shell reads),
  plus `tier`, `loop`, `samples`, `sampleRate`, `channels`, `bytes` and `sha256` for audits.
- `events`: every rules event that has a sound and the shell's own cues (`ui.tap`, `ui.keypad`,
  `ui.navigate`, `ui.blocked`, `fx.bubble`, `fx.wipe`, `fx.board-done`, `fx.chest`, `fx.buy`), each
  to its sounds and a `select` policy the shell applies: `streak` for `answer.correct` (pearl n for
  the n-th right answer in a row), `amount` for `coins.earned` (a coin, or the shower from five),
  `sequence` for `level.completed` (the fanfare, then one star per star earned). `monster.freed`
  plays `sfx/victory-sting` once; the shell keeps the music silent for the sting's
  `durationSeconds`, so that value is measured from the file, never typed.
- `voices.throttle`: each frequent sound's minimum interval and concurrency. A rules event and a
  shell cue for the same moment (`item.purchased` and `fx.buy`, `chest.opened` and `fx.chest`)
  share one sound whose interval keeps the second silent.
- `music.states`: the screen moods the shell passes to `setMusic`, each to a loop or `null`:

  | Mood       | Loop             |
  | ---------- | ---------------- |
  | `grotto`   | `music/grotto`   |
  | `map`      | `music/map`      |
  | `practice` | `music/practice` |
  | `battle`   | `music/battle`   |
  | `race`     | `music/battle`   |

  A mood the pack does not list (`results`, `finale`, …) plays the grotto loop (the shell's
  `musicFor`), so `music/finale` can arrive later without code changes.
  `crossfadeSeconds` is 1.2.

- `revision` is derived from the sound files' digests, so it changes exactly when a sound does.
- `decoded`: the worst case below.

`node scripts/audio/manifest.mjs --check` (the `audio` step of `npm run verify`) fails when the
committed manifest is stale or any rule breaks: contract IDs on the right bus, one mono 48 kHz Vorbis
stream per Ogg file with no tags but the encoder's, every effect encoded from its recipe's output
(which renders byte for byte), whole-frame loops, events and states naming known sounds, and the
decoded budget. `test/tooling/audio-pack.test.ts` also checks that the shell's own reader
(`parseAudioManifest`) accepts the manifest and its selection policies, and that every sound has
provenance and the user's approval.

## 4. Loudness and memory

| Tier        | Target                 | Sounds                                                     |
| ----------- | ---------------------- | ---------------------------------------------------------- |
| `music`     | -23 LUFS integrated    | grotto and battle loops, victory sting                     |
| `musicCalm` | -26 LUFS integrated    | practice loop: unobtrusive while the child thinks          |
| `feedback`  | -15 LUFS momentary max | chimes, coins, stars, fanfares, rewards                    |
| `character` | -16 LUFS momentary max | eggs, hatching, growing, monsters, Inkoustíci, Bublinka    |
| `soft`      | -18 LUFS momentary max | not quite, not now, hints, wiping: gentle, never punishing |
| `ui`        | -21 LUFS momentary max | taps, keys, screens, pages: frequent, so quiet             |

Loudness is measured with ITU-R BS.1770 (K-weighting, gating) on the mono file as a single channel,
as Dragon Valley measured its mono files, with a -1 dBTP true-peak ceiling (4× oversampled). Loops
are measured over two periods so the gate sees the seam. A few very percussive effects stop up to
1.5 dB short of their tier, where the true-peak ceiling and the limiter's range meet.

**Decoded-memory budget: 48 MiB** for every sound decoded at once (the SDK's default limit is
64 MiB). The pack uses 44.4 MiB: the music 38.2 MiB (grotto 11.6 MB, battle 11.0 MB, practice
8.6 MB, map 7.0 MB, sting 1.8 MB) and the 39 effects 6.2 MiB. An optional finale loop must fit in
the remaining 3.6 MiB (about 19 seconds of mono audio).

## 5. How the music was made

All on the authoring PC (NVIDIA RTX 4070 Ti SUPER), offline:

1. **ACE-Step 1.5** (`ace-step/ACE-Step-1.5` at `ca1e85f`) through its local API: the 4B
   `acestep-v15-xl-sft` DiT (int8 weight-only, CPU and DiT offload), 50 ODE steps, guidance 7.0,
   shift 3.0, the `acestep-5Hz-lm-1.7B` planner on vLLM, instrumental, an explicit BPM and key per
   track (grotto 96 BPM F major, practice 84 BPM F major, battle 132 BPM D minor, sting 120 BPM F
   major, map 104 BPM G major), 90-second takes (12 for the sting), two seeds per track. The captions are in
   `assets/audio/prompts/`.
2. **Loop cut** (`scripts/audio/authoring/loop.py`): librosa's beat tracker and a robust linear
   fit give the real tempo (ACE-Step lands about 1 % off the requested BPM), checked against a comb
   over the onset envelope's autocorrelation at every beat multiple up to 30 s; when they disagree by
   more than 0.2 % the comb wins (the map take's rocking rhythm fooled the tracker by 0.9 %, which
   would have put the seam a third of a second off the beat; the comb agrees with the earlier loops'
   fits within 0.01 BPM). The downbeat comes
   from low-frequency onsets, and a bar-aligned loop is chosen in the steady middle where the bar
   before the end sounds like the bar before the start and the bar after the end like the bar after
   the start. The tail is crossfaded (equal power, half a beat) into the audio just before the
   start, so the end flows into the first sample, and the length is rounded to whole frames. The
   measured seam drift is at most 5.3 ms (2.7 ms for the map).
3. **Mono** (`scripts/audio/authoring/mono.py`): (L+R)/2 with a phase check per octave band. The
   practice, battle and map takes had anti-phase mid or high frequencies (they would lose 4.6-8.7 dB
   in mono; the map 5.1 dB at 2 kHz),
   so a zero-phase spectral-balance EQ, applied circularly over the loop so the seam stays exact,
   restores every octave band to within 1.3 dB of the stereo balance.
4. **Loudness** to the tier, then **Vorbis** encoding with FFmpeg's libvorbis (bit-exact flags, no
   metadata). The Ogg is decoded again to confirm its exact length.
5. The sting is trimmed from its first note to 0.3 s after its ring-out falls 45 dB below its peak,
   with a short fade, then the same mono, loudness and encoding steps.

`assets/audio/provenance.json` (never shipped) records, for every sound, the tool and the model
revisions with checkpoint digests, the exact caption and settings with the seed, the digest of the
model's output, every processing step with its parameters, the shipped file's digest and the user's
approval. GPU generation is not bit-identical across machines, so the committed bytes with their
digests are the asset.

The authoring scripts are Python (librosa, soundfile, pyloudnorm, SciPy, NumPy) plus FFmpeg; they are
not part of the build or the gate.

## 7. How the effects are made

The effects are synthesized by Dragon Valley's audio engine, ported unchanged to
`scripts/audio/synth/` (MIT, same author): additive, FM, oscillator and noise voices with
envelopes and filters, tracks with sends, reverb buses, a master EQ, loudness normalization with a
soft look-ahead limiter (at most 6 dB off a peak) and a -1 dBTP true-peak ceiling, short fades,
TPDF dither and 16-bit PCM. Only IEEE-754 basic arithmetic and seeded integer generators are used,
so every platform renders identical PCM. The PCM is then encoded to Vorbis like the music.

- **Recipes**: one JSON file per effect in `assets/audio/recipes/sfx/` (its notes, voices,
  scatters, buses and loudness tier) and the shared instrument library
  `assets/audio/recipes/_patches.json`: Dragon Valley's instruments (celesta, glockenspiel,
  marimba, kalimba, harp, glass, brass, pizzicato …) plus four water patches, `bubble` (a sine
  whose pitch rises as the bubble shrinks), `droplet`, `splash` and `swish`. Never edit an
  effect's file; edit its recipe and render again.
- **Commands**: `node scripts/audio/sfx.mjs` renders every effect (`--only a,b` for a few,
  `--wav <dir>` to keep the PCM for an audition) and encodes the effects whose PCM changed with
  FFmpeg's libvorbis (quality 5, bit-exact flags, no metadata; FFmpeg from `FFMPEG` or the
  `PATH`). It decodes each new Ogg again, checks its length and that its true peak stays below
  -0.5 dBTP, and writes `assets/audio/synth-provenance.json` (never shipped: the engine, each
  recipe's resolved digest, the seed, the measured loudness, the PCM's digest, the Ogg's digest
  with the PCM digest it was encoded from and the encoder, and the user's approval).
  `--approve <gate> <answer>` records an audition gate's answer for the rendered effects; a
  changed effect loses its approval until it is auditioned again.
- **The check**: `--check`, run by the manifest check and the tests, needs no FFmpeg. It renders
  every recipe again in memory and fails unless each committed Ogg was encoded from exactly that
  PCM, is the recorded file and has the PCM's length.
- **Re-voicing**: the designs follow Dragon Valley's effects, which children already liked, moved
  to the sea: chimes become pearls with a droplet, the swoosh becomes water, rewards gain rising
  bubbles, and misses stay soft "bloops", never a buzzer.
